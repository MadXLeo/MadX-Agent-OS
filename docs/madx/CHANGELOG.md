# MadX change log

## 0.1.0-alpha — in development, 2026-10-27

- Completed desktop/CLI/bridge display-copy migration, keeping persisted identifiers and all
  command IDs. Added old/new app-name and presentation compatibility fixes.
- Exported the supplied artwork to PNG, ICO, ICNS and Plymouth resources with hash verification.
- Added staged, conflict-safe Linux command/service/path aliases without moving user state.
- Updated Arch packages, macOS bundle checks, release artifacts, registry policy, os-release and
  ISO metadata together; preserved encrypted interactive installation and rollback layout.
- Added a fresh graphite/cyan Linux theme; saved legacy themes and their IDs remain usable.
- Passed 4,915 renderer tests, the 89-test main-process migration recheck, typecheck and production
  build. Documented 128 reproduced Windows baseline failures and unrun Linux/native/VM gates.
- Added explicit legacy-copy exceptions, native source checks, release gates and a gated Phase 2 plan.

- Recorded the clean upstream revision, feasible baseline results, feature families, system-critical
  migration contracts, target architecture, security boundaries and open installer investigation.
- Added centralized MadX product identity, generated consumers and CI consistency verification.
- Integrated the supplied metallic artwork into shell branding and a monogram favicon.
- Migrated selected desktop/setup translations, window/app/notification names and About provenance.
- Added conservative Chromium profile reuse, MadX environment aliases and dual-identity niri rules.
- Set fresh desktop preferences to graphite with cyan/ice accents while keeping saved settings.
- Added regression coverage for profile preservation/refusal, environment precedence, translated
  identity and user text, startup ordering, and compositor/dock title agreement.
- Added a source branding audit with explicit review categories and continuation instructions.

This is not a release announcement. Model management, LoRA/ComfyUI/training, expanded intelligence,
self-development and independent OS images/installers remain unimplemented. See VALIDATION.md.
